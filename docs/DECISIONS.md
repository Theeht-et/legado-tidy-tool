## v1 决策记录（ADR）

> 本文件是活的，每次做出影响架构的决定就追加一条，不要删旧条目（只标记「已废弃」）。

### D1 只做 Windows 桌面端（不再做 Android / KMP）

- 日期：2026-10-28
- 决定：取消手机端，工程改为三个普通 JVM 模块（`core` / `engine` / `desktop`），不再使用 Compose Multiplatform 的三层源集。
- 理由：手机端要复用引擎，必须把 Legado 自己的 `BaseSource`/`AppConfig`/`appDb`/`JsExtensions` 一起拉进 androidMain，并补齐 Room/KSP/Glide/media3/cronet 全套依赖，等于在工程内重建 Legado 的 app module；且校验是 3000 源 × 200 并发的网络密集任务，不适合手机（前台服务、省电白名单、流量、发热）。
- 代价：无 Android 端口。若将来要做，`core` 可原样复用，`engine` 需按上面的方式重新评估。

### D2 引擎选「最新稳定版源码」，直接 vendor 进仓库

- 日期：2026-10-28
- 决定：不复用什么「最新 master」、不用 submodule、不依赖构建期网络。把 `LegadoTeam/legado` 指定 tag 的引擎源码目录**提交进本仓库**的 `vendor/legado/`。
- 基线：tag `3.26101819`（commit `a7d37f1707a70a459ad708f4fe79341d1e42d716`）。
- 理由：编进产物的是源码，pin 一次即定死行为；补全层的签名对齐是一次性工作；同一份书源 + 同一引擎 = 可复现结果。vendor 进仓库换来的是「离线可构建、clone 即完整」。
- 代价：仓库变大；升级引擎是一次显式动作（见 `docs/ENGINE.md`）。

### D3 S4 导出：本地文件为主，直链为可选通道

- 日期：2026-10-28
- 决定：默认导出本地 JSON 文件（用户手动导入阅读 App）；「直链」作为可选通道保留在接口层（`DirectLinkPublisher`），UI 只在用户显式选择直链时出现。
- 二维码：只在拿到可访问 URL 时才显示（QR 上限约 2.9KB，装不下几千个源；纯本地路径也无法被手机端读取）。
- 理由：去掉第三方网盘的 7 天有效期与接口变更这个单点依赖；直链能力保留但不阻塞主流程。

### D4 许可证：GPL-3.0

- 日期：2026-10-28
- 决定：整个项目以 GPL-3.0 发布，分发时提供完整对应源码。
- 理由：Legado 上游为 GPL-3.0，把其引擎源码编译进产物并分发构成衍生作品。内部自用不受约束，但对外发布必须同许可证开源。
- 影响：不能闭源、不能只发二进制；`vendor/legado/LICENSE` 与上游声明必须随仓库保留。

### D5 取消 Android 端

- 日期：2026-10-28
- 决定：不做 Android 端，只做桌面端。
- 理由：3000 个源 × 200 并发的校验在手机上是前台服务常驻 + 发热 + 流量；且 Legado 的 Android 平台类无法直接复用，补全量不比桌面端小。
- 代价：手机上只能「导出到本地再导入」。
- 关系：D1 已定该项，本条把理由与代价写死。

### D6 S4 默认产出本地文件，直链为可选通道

- 日期：2026-10-28
- 决定：S4 默认产出本地 JSON 文件；直链为可选通道。
- 理由：二维码容量上限约 2.9KB，装不下书源 JSON；书源只有走 HTTP(S) 订阅地址时二维码才有意义。
- 界面行为：「直链」填写框为空时只给「导出文件」，填了才给「复制导入链接」。
- 关系：D3 定了方向，本条把界面行为写死。

### D7 v3 阶段式工作流与 UI 重构

- 日期：2026-10-30
- 状态：实施中
- 决定：以 v3 原型作为 Compose Desktop 的 UI 和交互基准；按「导入 → 去重审核 → 校验审核 → 整理预览 → 导出」阶段推进。系统默认生成保留/删除建议，用户可以覆盖；进入下一阶段时，才将当前阶段标记删除的条目从内存工作池移除。
- 界面约束：顶部阶段栏；左侧书源表格；右侧详情/编辑；底部操作栏。「开始去重」与「查看导入信息」并列；重复组靠近显示并提供组内对比；列表显示源名/URL、类型、分组、状态、耗时、建议、操作；不显示底部统计/批量审核行，也不在底部提供重复组对比。
- 整理规则：只执行用户显式勾选的规则；预览可编辑，确认后才应用到工作池。输入文件永远不被覆盖。
- 架构约束：优先复用现有引擎与 core 逻辑；为 GUI 增加阶段执行入口，但保持 CLI 完整流水线；不做无价值分层，不在本轮修改 vendor 源码。
- 验收：阶段转换后删除标记生效，稳定 ID 保证删除后不发生结果错位；真实引擎校验与导出字段保留通过测试；编译、单测和 Windows 便携包通过。
