## v1 决策记录（ADR）

> 本文件是活的，每次做出影响架构的决定就追加一条，不要删旧条目（只标记「已废弃」）。

### D1 只做 Windows 桌面端（不再做 Android / KMP）

- 日期：2026-10-28
- 决定：取消手机端，工程改为三个普通 JVM 模块（`core` / `engine` / `desktop`），不再使用 Compose Multiplatform 的三层源集。
- 理由：手机端要复用引擎，必须把 Legado 自己的 `BaseSource`/`AppConfig`/`appDb`/`JsExtensions` 一起拉进 androidMain，并补齐 Room/KSP/Glide/media3/cronet 全套依赖，等于在工程内重建 Legado 的 app module；且校验是 3000 源 × 200 并发的网络密集任务，不适合手机（前台服务、省电白名单、流量、发热）。
- 代价：无 Android 端口。若将来要做，`core` 可原样复用，`engine` 需按上面的方式重新评估。

### D2 引擎选「最新稳定版源码」，直接 vendor 进仓库

- 日期：2026-10-28
- 决定：不复用什么「最新 master」、不用 submodule、不依赖构建期网络。把 `LegadoTeam/legado` 指定 tag 的引擎源码目录**提交进本仓库**的 `vendor/legado/`。
- 基线：tag `3.26101819`（commit `a7d37f1707a70a459ad708f4fe79341d1e42d716`）。
- 理由：编进产物的是源码，pin 一次即定死行为；补全层的签名对齐是一次性工作；同一份书源 + 同一引擎 = 可复现结果。vendor 进仓库换来的是「离线可构建、clone 即完整」。
- 代价：仓库变大；升级引擎是一次显式动作（见 `docs/ENGINE.md`）。

### D3 S4 导出：本地文件为主，直链为可选通道

- 日期：2026-10-28
- 决定：默认导出本地 JSON 文件（用户手动在阅读 App 里导入）；「直链」作为可选通道保留在接口层（`DirectLinkPublisher`），UI 只在用户显式选择直链时出现。
- 二维码：只在拿到可访问 URL 时才显示（纯本地导出时二维码无处可编码——QR 上限约 2.9KB，装不下书源 JSON，也编码不了本地路径）。
- 理由：去掉第三方网盘的 7 天有效期与接口变更这个单点依赖；直链能力保留但不阻塞主流程。

### D4 许可证：GPL-3.0

- 日期：2026-10-28
- 决定：整个项目以 GPL-3.0 发布，分发时提供完整对应源码。
- 理由：Legado 上游为 GPL-3.0，把其引擎源码编译进产物并分发构成衍生作品。内部自用不受约束，但对外发布必须同许可证开源。
- 影响：不能闭源、不能只发二进制；`vendor/legado/LICENSE` 与上游声明必须随仓库保留。
