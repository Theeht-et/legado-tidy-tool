# 产品规划（v3 工作流基线，2026-10-30）

## 产品目标

将本地 Legado 书源导入后，按「去重 → 校验 → 整理 → 导出」逐阶段处理。系统先提出建议；用户可以修改；确认进入下一阶段时，才把该阶段标记删除的书源从当前工作池移除。原始导入文件始终不覆盖。

## 总体交互约束

- 以 `docs/prototypes/legado-tidy-tool-ui-v3.html` 的 v3 交互原型为视觉和操作基准；正式实现使用 Compose Desktop，不直接嵌入 HTML。
- 单窗口处理工作区：顶部阶段栏，中部左侧书源列表、右侧详情/编辑区，底部当前阶段操作栏。
- 书源列表字段固定为：**源名 / URL / 类型 / 分组 / 状态 / 耗时 / 建议 / 操作**；每行提供「详情」和「编辑」。
- 去重候选必须靠近显示或按重复组分组；「对比重复组」放在对应组内，不放在页面最底部。
- 不显示「当前书源 / 显示数量 / 已选数量 / 已移出数量 / 批量审核」组成的底部统计行；不提供独立的「取消选择」按钮。
- 「开始去重」放在底部操作栏，与「查看导入信息」并列。
- 系统给出默认建议，用户可以覆盖建议。除进入下一阶段时的提交操作外，建议/删除标记仅是当前工作集内的待提交决定。

## 工作流

### S0 导入

- 支持现有 `SourceIO` 所支持的数组、单对象及包装对象 JSON。
- 读取并保存原始文件路径及原始书源快照；后续操作仅修改内存工作集，不覆盖输入文件。
- 解析失败时保留错误详情，禁止开始处理。

### S1 去重与审核

继续使用现有 `Deduper` 三层候选算法：

1. 完全重复；
2. 行为字段指纹相同；
3. 行为规则高度相似（默认 Jaccard ≥ 0.92）。

- 去重计算后，重复候选相邻显示并按组呈现。
- 每组自动采用 `DedupGroup.keep` 作为默认保留建议：建议保留项标为「保留」，其他候选标为「待删除」。
- 组内提供并列对比；详情面板展示原始字段差异。用户可以改保留项，也可以把多项都设为保留。
- 点击「确认去重并进入校验」时，才将所有待删除项从**当前工作池**移除。每个工作集条目使用稳定 ID 关联，不能在删除后继续依赖会改变的列表下标。
- 去重算法本身只生成分组与推荐，不在 core 中擅自删除数据。

### S2 校验与审核

- 使用固定版本的真实 `LegadoProbeEngine`，不使用模拟数据。
- 展示状态、响应耗时、建议和失败详情；可编辑源字段与删除标记。
- 默认将确定无法完成当前工具目标的结果标记为待删除：`NO_SEARCH_URL`、`UNSUPPORTED`、`PARSE_EMPTY`。
- `TIMEOUT`、`NETWORK`、`HTTP_ERROR` 和一般 `ERROR` 默认保留并建议复核，避免网络波动、反爬或内部异常造成误删。用户可以逐条修改建议。
- 点击「确认校验并进入整理」时，才把标记删除项从当前工作池移除。
- 校验并发、关键词、超时、代理和校验深度沿用现有设置；长任务必须显示进度并允许停止。

### S3 整理与预览

整理规则由用户显式勾选后执行。未勾选的规则不得被隐式应用。

可选择的规则至少包括：

- 清理名称中的图标与装饰；
- 清理常见广告宣传词；
- 规范多余空格与标点；
- 保留原有分组；
- 按书源类型重新分组；
- 按响应耗时升序排序。

「保留原有分组」与「按类型重新分组」互斥。所有规则默认不自动覆盖原字段。点击「生成整理预览」后计算候选结果，在列表/详情中显示新旧值并允许逐条编辑；点击「确认整理并进入导出」后才把预览结果应用到工作池。排序规则关闭时保留用户当前顺序。

### S4 导出

- 仅导出经过阶段确认后的当前工作池。
- 默认写本地 JSON；沿用现有导出目录和文件命名规则。
- 保留所有未知 JSON 字段。只改用户确认的名称、分组、排序等字段。
- 可选直链功能和现有设置保留；导出失败必须显示可读错误，不得覆盖输入文件。
- 导出完成后显示路径、源数量与打开导出目录的入口。

## 实现边界

- 现有 `Deduper`、`LegadoProbeEngine`、`Exporter` 和 JSON 模型优先复用。
- UI 需要阶段暂停，因此不能继续把 `Pipeline.run()` 作为 GUI 唯一入口；应增加可独立执行的阶段能力，且保留 CLI 的一次性流水线行为。
- 只在存在独立责任时拆文件，不为了目录层级或架构形式增加 UseCase、Repository 等层。
- 不在本轮顺手升级或手改 `vendor/legado/`、`vendor/glue/`。
- 工作集书源用稳定 ID；Deduper、ProbeResult 和 Organizer 的临时索引只能在单次计算边界内使用，写回 UI 状态前必须映射回稳定 ID。

## 验收标准

1. 书源导入后不会直接自动删除源；去重建议可修改，确认阶段后删除真正应用于当前工作池。
2. 重复候选相邻显示，组内对比正确；多项保留是允许的。
3. 校验使用真实引擎；超时/网络错误不默认当作坏源删除；阶段转换后不发生结果错位。
4. 整理规则逐项可选；没有选择的规则不执行；预览与最终导出内容一致。
5. 输入文件不被覆盖，未知 JSON 字段保留，设置/报告/CLI 原有能力不无故退化。
6. 单元测试覆盖阶段转换、删除后稳定 ID 映射、建议覆盖、整理规则组合、导出字段保留。
7. GitHub Actions 中编译与测试、Windows 便携包均成功，并用真实书源文件完成一次端到端手动验收。
